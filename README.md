## Часть 1. C++ (наследование и полиморфизм)

## Тема проекта
**Симулятор умного дома**

Предметная область описывает виртуальный умный дом, в котором есть комнаты,
устройства и сценарии автоматизации. Пользователь может включать и выключать
устройства, ломать и чинить их, а также запускать сценарии, которые управляют
устройствами целой комнаты.

Эта часть — переработка проекта из ЛР 3. Появляется иерархия классов:
абстрактный базовый класс `BaseDevice` и его наследники `SmartLamp` и
`SmartThermostat`. Осваиваются конструкторы, копирование, строки, `this` и
статические члены класса.

## Структура проекта

---


### 1. `BaseDevice` (Устройство) — абстрактный класс
**Ответственность:** описывает общее для всех умных устройств: имя, мощность, состояние, сломанность.

**Поля (все private):**
- `m_id` — уникальный идентификатор (генерируется статическим счётчиком);
- `m_name` — название устройства;
- `m_isOn` — включено ли устройство;
- `m_isBroken` — сломано ли устройство;
- `m_powerConsumption` — потребляемая мощность (Вт);
- `m_roomName` — `std::shared_ptr<std::string>` — название комнаты (используется для демонстрации копирования).

**Статические члены:**
- `s_lastId` — общий счётчик созданных устройств (`inline static int`);
- `NextId()` — статический метод генерации следующего ID.

**Чисто виртуальные методы (делают класс абстрактным):**
- `virtual std::string GetType() const = 0;`
- `virtual std::unique_ptr<BaseDevice> Clone() const = 0;`

**Виртуальные методы:**
- `virtual std::string Describe() const;` — текстовое описание устройства.

**Содержательные методы:**
- `TurnOn()` — включить устройство;
- `TurnOff()` — выключить устройство;
- `Break()` — сломать устройство;
- `Repair()` — починить устройство;
- `RenameRoom(...)` — переименовать комнату.

**Конструкторы/деструктор:**
- с параметрами;
- копирования (глубокое копирование `m_roomName`);
- перемещения;
- оператор присваивания с проверкой `this == &other`;
- **виртуальный** деструктор.

**Модификатор `protected`:**
- `protected std::string FormatHeader() const;` — метод, который используется
  наследниками для формирования строки описания. Снаружи (`book.FormatHeader()`)
  он недоступен. Он не `private`, потому что нужен `SmartLamp` и
  `SmartThermostat`, и не `public`, потому что это деталь реализации иерархии.

---

### 2. `SmartLamp` (Умная лампа) — наследник
**Ответственность:** описывает умную лампу с регулируемой яркостью.

**Поле:**
- `m_brightness` — яркость (0–100).

**Переопределяет:**
- `GetType()` — возвращает `"Умная лампа"`;
- `Describe()` — вызывает `BaseDevice::Describe()` и дополняет яркостью;
- `Clone()` — возвращает `std::make_unique<SmartLamp>(*this)`.

**Содержательный метод:**
- `SetBrightness(...)` — изменить яркость с проверкой диапазона.

---

### 3. `SmartThermostat` (Термостат) — наследник, **`final`**
**Ответственность:** описывает умный термостат с целевой температурой.

**Поле:**
- `m_targetTemp` — целевая температура.

**Переопределяет:**
- `GetType()` — возвращает `"Термостат"`;
- `Describe()` — **полностью заменяет** описание, не вызывая `BaseDevice::Describe()`;
- `Clone()` — возвращает `std::make_unique<SmartThermostat>(*this)`.

**Содержательный метод:**
- `SetTargetTemp(...)` — изменить целевую температуру с проверкой диапазона (5–30 °C).

**`final`** на классе запрещает дальнейшее наследование (от термостата нельзя
унаследоваться).

## Проверяемые правила предметной области

1. **Нельзя включить сломанное устройство.**
   Проверка в `BaseDevice::TurnOn()`: если `m_isBroken == true`, выводится
   сообщение об ошибке, и состояние не меняется.

2. **Яркость лампы — от 0 до 100.**
   Проверка в `SmartLamp::SetBrightness()`.

3. **Целевая температура термостата — от 5 до 30 °C.**
   Проверка в `SmartThermostat::SetTargetTemp()`.

## Что демонстрирует `main.cpp`

1. **Порядок вызова конструкторов и деструкторов** — при создании
   `SmartLamp` сначала выполняется `BaseDevice()`, потом `SmartLamp()`.
   При уничтожении — в обратном порядке.

2. **Виртуальный деструктор** — объект `SmartLamp` создан через
   `std::unique_ptr<BaseDevice>`. При `ptr.reset()` вызывается корректный
   деструктор наследника, затем базового класса.

3. **Поверхностное и глубокое копирование:**
   - поверхностное — `shared_ptr` на комнату делится между двумя устройствами
     (изменение комнаты через копию меняет её и у оригинала);
   - глубокое — через `Clone()`: копия получает **собственный** экземпляр
     `std::string` комнаты (изменение через копию не затрагивает оригинал).

4. **Оператор присваивания и `this`:**
   - проверка самоприсваивания (`if (this == &other) return *this;`);
   - возврат `*this`.

5. **Переопределение метода:**
   - `SmartLamp::Describe()` вызывает `BaseDevice::Describe()`;
   - `SmartThermostat::Describe()` — не вызывает.

6. **Статические члены** — счётчик `NextId()` корректно нумерует все созданные
   объекты, включая копии.

7. **Строки** — `find()`, `substr()`, конкатенация с `std::to_string`.

8. **`final`** — `SmartThermostat` помечен `final`; попытка унаследоваться
   от него даст ошибку компиляции.

## Правило трёх/пяти/нуля

В `BaseDevice` написаны **все пять** специальных операций:

- деструктор (`virtual ~BaseDevice()`);
- конструктор копирования;
- конструктор перемещения;
- оператор присваивания копированием;
- (оператор присваивания перемещением — по умолчанию).

Это **правило пяти**: у класса есть ресурс (`shared_ptr` на комнату), и
копирование должно быть глубоким, а перемещение — эффективным.

В наследниках (`SmartLamp`, `SmartThermostat`) написаны только конструкторы
копирования; остальные специальные операции — по умолчанию (правило нуля там,
где возможно). Это допустимая комбинация.

## Сборка и запуск

### Требования
- Компилятор с поддержкой C++17 (Visual Studio 2019/2022, GCC 9+, Clang 10+).

### Сборка в Visual Studio
1. Открой файл `lab-04-cpp.vcxproj` в Visual Studio.
2. Проверь свойства проекта:
   - **C/C++ → Язык → Стандарт языка C++** — `ISO C++17` или новее
     (нужно для `inline static`).
   - **Компоновщик → Система → Подсистема** — `Консоль (/SUBSYSTEM:CONSOLE)`.
3. Собери проект: **Сборка → Собрать решение** (или `Ctrl+Shift+B`).
4. Запусти: **Отладка → Запуск без отладки** (или `Ctrl+F5`).

### Сборка через командную строку (GCC/Clang)
```bash
g++ -std=c++17 -Wall -Wextra -o lab-04 main.cpp BaseDevice.cpp SmartLamp.cpp SmartThermostat.cpp
./lab-04
